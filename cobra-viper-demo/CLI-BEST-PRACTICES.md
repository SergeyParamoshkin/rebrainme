# Свойства хорошей CLI утилиты

## 1. Интуитивность и простота использования

### Принцип наименьшего удивления
- Команды должны вести себя предсказуемо
- Следование общепринятым соглашениям (флаг `-h` для помощи, `-v` для версии)
- Консистентность в названиях команд и флагов

### Примеры в нашем приложении:
```bash
# Интуитивные команды
./app serve           # Очевидно - запускает сервер
./app db connect      # Очевидно - подключение к БД
./app config show     # Очевидно - показывает конфигурацию
```

## 2. Информативная система помощи

### Автоматическая генерация help
```bash
./app --help          # Общая помощь
./app serve --help    # Помощь по конкретной команде
./app db --help       # Помощь по группе команд
```

### Компоненты хорошей помощи:
- **Краткое описание** - что делает команда
- **Синтаксис использования** - как вызвать
- **Список флагов** - доступные опции
- **Примеры** - реальные сценарии использования

## 3. Структурированность команд

### Иерархия команд (как в Git)
```bash
app
├── serve                    # Простая команда
├── db                       # Группа команд
│   ├── connect
│   ├── migrate
│   ├── backup
│   └── status
└── config                   # Группа команд
    ├── show
    ├── get
    └── list
```

### Преимущества:
- Логическая группировка функционала
- Масштабируемость
- Простота навигации

## 4. Гибкая конфигурация

### Множественные источники конфигурации
```bash
# 1. Значения по умолчанию (в коде)
viper.SetDefault("server.port", 8080)

# 2. Конфигурационный файл
server:
  port: 8080

# 3. Переменные окружения
export DEMO_SERVER_PORT=9000

# 4. Флаги командной строки (высший приоритет)
./app serve --port 3000
```

### Приоритеты (от низшего к высшему):
1. Defaults → 2. Config File → 3. ENV → 4. Flags

## 5. Обратная связь и информативность

### Verbose режим
```bash
./app --verbose serve
# Выводит:
# - Используемый конфиг файл
# - Текущие настройки
# - Детали операций
```

### Статус-коды выхода
```go
// Успех
os.Exit(0)

// Ошибка
os.Exit(1)
```

### Прогресс выполнения
```bash
./app db migrate
# Выполнение миграций базы данных...
# ✓ 001_create_users_table.sql
# ✓ 002_add_email_to_users.sql
# ✓ 003_create_products_table.sql
# Миграции успешно применены!
```

## 6. Безопасность

### Защита чувствительных данных
```go
// Скрытие паролей в выводе
password := viper.GetString("database.password")
if password != "" {
    fmt.Printf("Password: %s\n", strings.Repeat("*", len(password)))
}
```

### Безопасные значения по умолчанию
- Не хранить пароли в коде
- Использовать переменные окружения для секретов
- Предупреждать о небезопасных операциях

## 7. Валидация и обработка ошибок

### Валидация аргументов
```go
var dbBackupCmd = &cobra.Command{
    Use:   "backup [filename]",
    Args:  cobra.MaximumNArgs(1),  // Максимум 1 аргумент
    // или
    Args:  cobra.ExactArgs(2),      // Ровно 2 аргумента
    Args:  cobra.MinimumNArgs(1),   // Минимум 1 аргумент
}
```

### Информативные сообщения об ошибках
```bash
# Плохо
Error: failed

# Хорошо
Error: Failed to connect to database at localhost:5432
Reason: Connection refused
Suggestion: Check if PostgreSQL is running
```

## 8. Производительность

### Быстрый запуск
- Ленивая инициализация
- Загрузка только необходимых модулей
- Минимальные зависимости

### Эффективность
```go
// Graceful shutdown для сервера
signal.Notify(sigint, os.Interrupt)

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
```

## 9. Переносимость

### Кроссплатформенность
- Работа на Linux, macOS, Windows
- Использование path/filepath вместо hardcoded путей
- Учёт различий в переменных окружения

### Минимальные зависимости
```go
// go.mod - только необходимое

    github.com/spf13/cobra v1.8.0

```

## 10. Тестируемость

### Разделение логики
```go
// Команда вызывает функцию, а не содержит логику
var serveCmd = &cobra.Command{
    Run: runServer,  // Функцию можно тестировать отдельно
}

func runServer(cmd *cobra.Command, args []string) {
    // Логика здесь
}
```

### Моки и заглушки
- Возможность подмены конфигурации
- Тестовые режимы (dry-run)

## 11. Документация

### Самодокументируемость
```go
var dbMigrateCmd = &cobra.Command{
    Use:   "migrate",
    Short: "Выполнить миграции БД",
    Long: `Выполняет миграции базы данных в правильном порядке.
    
Поддерживает режим предпросмотра (--dry-run) для проверки
без реального выполнения.`,
    Example: `
  # Выполнить все миграции
  app db migrate
  
  # Предпросмотр миграций
  app db migrate --dry-run
  
  # Мигрировать до версии 3
  app db migrate --version 3`,
}
```

## Антипаттерны CLI (чего избегать)

### ❌ Неинформативные сообщения
```bash
# Плохо
Error: Something went wrong

# Хорошо
Error: Cannot bind to port 8080: Address already in use
```

### ❌ Отсутствие --help
```bash
# Плохо
./app --help
Unknown flag: --help

# Хорошо
./app --help
# Показывает полную документацию
```

### ❌ Деструктивные действия без подтверждения
```bash
# Плохо
./app database drop  # Сразу удаляет

# Хорошо
./app database drop
> This will permanently delete all data. Continue? [y/N]:
```

### ❌ Молчаливые сбои
```bash
# Плохо
./app backup
# (ничего не выводит при ошибке)

# Хорошо
./app backup
Error: Backup failed: Insufficient disk space (need 2GB, have 500MB)
```

### ❌ Несогласованные флаги
```bash
# Плохо
./app serve --p 8080        # Короткий флаг
./app db connect --port 5432 # Длинный флаг

# Хорошо - консистентность
./app serve --port 8080
./app db connect --port 5432
```

## Резюме

Хорошая CLI утилита должна быть:
1. **Интуитивной** - пользователь должен угадывать, как она работает
2. **Информативной** - давать достаточно информации о происходящем
3. **Безопасной** - защищать от случайных ошибок
4. **Гибкой** - поддерживать разные способы конфигурации
5. **Документированной** - иметь встроенную помощь и примеры
6. **Эффективной** - быстро запускаться и работать
7. **Расширяемой** - легко добавлять новый функционал

Cobra и Viper помогают реализовать большинство этих свойств "из коробки"!
